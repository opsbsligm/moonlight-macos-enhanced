# macOS 键鼠全链路审查与整理（2026-09-27）

**后续现场反馈推翻了“现有修复足以处理连击 C”的预期。** 最新日志、默认配置回放、防护调整与未确认边界见 [连击 C 现场回归](click-c-incident-2026-09-27.md)。本页的覆盖和通过结果属于阶段性验证，不是实机验收。

本轮接续 [第一次键鼠加固](input-hardening-2026-09-27.md)，按事件入口、状态所有者、异步边界、发送端与退出路径核对覆盖范围，修复旁路缺陷并减少重复实现。审查对象是当前 **macOS 增强版的有效键鼠通路**，包含手柄模拟键鼠；不是对视频、网络、音频及整个仓库作无缺陷保证。

## 再次复查补充

用户要求再次检查后，发现并修复了三个此前覆盖不足的捕获边界：

1. **失焦期间 Caps Lock 切换**：如果另一应用收到锁定切换，本地保存的旧状态会吞掉重新捕获后的第一次切换。现在重新捕获时读取当前本地 Caps Lock 状态作为基准，不重放捕获外输入，也不假设宿主初始锁定状态。
2. **位移跨捕获周期残留**：解除捕获后立即重新捕获，期间没有显示帧或手柄定时器回调时，GC 位移累积和三路小数残差不会自然归零。现在捕获状态真正变化时清空缓存；GC producer、显示帧 consumer 和清理共享会话锁，避免清理后补入旧缓存。MFi 定时器残差也在解除捕获时清理；相同捕获状态的重复赋值不会丢掉新运动。
3. **绝对坐标缓存跨周期发送及错误去重**：合并位置包增加捕获代次校验；切换时丢弃旧待发位置并清除坐标去重记录。新周期即使位置与旧周期相同，也会正常发送。

`input-boundary-tests.py` 已扩展为 30 项结果，执行抽取的生产状态逻辑、累积器及合并坐标方法；含暂停真实串行队列后切换捕获的复现场景。负向验证分别撤销 Caps Lock 基准刷新、位移缓存清理、绝对坐标代次校验，要求每个旧缺陷被独立检出。手柄所有权探针增加了定时器未运行时的残差清理断言。显示帧锁与回调接线另作源码检查，不将它们称为实物压力测试。

二次完整输入回归的 45 条命令全部通过；四种负向变体均被检出。最终 Release 构建成功，第一方告警审计及严格签名校验通过。验证日志使用本机 `build-input-review/recheck-*` 前缀，原 `full-review-*` 保留为上一轮记录。实物串流及高报告率延迟仍未实测，不能把这些结果表述为硬件问题已经根治。

全项目约束使用已安装 PyYAML 的 `/opt/homebrew/bin/python3` 复核后，仍仅有原有视频增强报告脚本未注册 CI 的两项失败；默认 Python 缺少 PyYAML 曾导致工作流审计无法运行，已排除这一环境问题，未修改系统依赖。

## 尚需实际设备验证的边界

- AJAZZ 接收器与两台宿主的真实左键、双击、拖拽及 C 输入，本轮没有启动串流复测。
- C 来源过滤需要已有 Input Monitoring 授权；来源证据缺失或冲突时保留键盘输入。无法据此保证未授权状态消除设备幽灵 C。
- CoreHID 主线程交接的高报告率延迟、系统焦点/Space 的所有组合、GC 与 AppKit 回声到达次序，以及两只设备同时操作，需要实物测量。保留的 80ms 跨源回声抑制仍是兼容策略，不是设备事件唯一 ID。
- Caps Lock 转发本地切换事件，不代表已获知或自动校准宿主初始锁定状态；原始 HID 的未知/不完整报告拒绝解析，不冒充已支持所有固件格式。
- 主仓库原有视频增强报告测试仍独立记录；它不属于本轮键鼠修复。子模块的输入修改仍需与主仓库一起保存，不能仅保存 gitlink。


## 串流边缘控制栏恢复（2026-09-27）

用户确认连击误发 C 已解决，随后反馈靠近边缘自动呼出的控制栏不可用。

- 启动时窗口已全屏，`connectionStarted` 重置并隐藏控制栏后会跳过窗口模式应用；重置方法现在主动请求可见性恢复，并沿用已有延迟重试。
- 相对鼠标模式把系统指针固定在中心，原检测及停留定时器却继续读取该固定坐标。新增独立的本地相对位置累计，四边钳制，事件检测和定时器复核共用位置；不改变发给主机的鼠标位移。
- 唤出后将本地指针放在展开的控制柄上，避免下一次移动从中心立即重新捕获。该位置只是本地控制栏的感应坐标，不代表主机端真实鼠标位置。
- 捕获、释放、模式变化和会话销毁清除计时/位置；捕获回中后忽略 120ms 位移。拖拽不触发；保留原来 24pt 感应带、2pt 贴边、150ms 停留、30pt 推压和单事件 6pt 封顶。
- 修正上下边推压的 deltaY 符号（AppKit 鼠标位移向下为正，视图 Y 向上为正）。

验证：原 27 项几何检查、新增 28 项生产方法运行回放均通过。将事件位置或停留复核改回固定系统指针，同一回放会失败。生命周期接线单独检查；10 项键鼠专项回归通过，Release 构建成功，一方警告为 0，严格签名验证成功。

证据位于 `build-input-review/edge-restore-*`。自动回放验证不等于用户串流手感验收；全屏原生面板、Space 切换和真实远端鼠标速度仍需实机观察。


### 后续：按钮可见，但靠近悬停不展开

用户实测反馈上一版只恢复了显示。进一步修正：24pt 感应带现在真正用于 150ms 悬停触发，同时覆盖按钮交互区；2pt 仅限制快速推压手势。原实现把悬停也卡在最外侧 2pt，与靠近按钮的操作不一致。原生按钮悬停回调现在在游戏和桌面模式都能安全释放捕获（按住鼠标时不释放），并订阅 `NSTrackingMouseMoved`。

验证扩展为 27 项几何与 36 项运行检查，运行检查直接执行生产 hover 回调，包含距离边缘 10pt 停住、靠近按钮停住、两种鼠标模式、按住按键及重复悬停。恢复旧的 2pt 悬停门槛或桌面专用释放条件，回放均失败。六项相关回归与本地化审计通过。新增 `Edge sensor hover armed` 日志用于区分进入感应区和最终展开，避免只凭按钮可见判断完成。真实串流鼠标位置与本地相对累计仍不等价，不能将这些回放视为实机验收。


### 后续：首次触发后难以再次触发

现场 pid 43080 在 17:38:07 记录一次 edge-sensor-push，17:38:10 又发生一次原生按钮悬停释放；会话汇总 capture=3 / uncapture=3，说明并非始终卡在释放态。代码复现的断点是从 dock 返回后 `captureMouse` 将本地感应位置也重置为中心，用户在边缘附近的小幅移回不足以重新到达感应区；拖拽分支也存在同样的位置重置。

修复：收起前保存返回点，捕获成功后将本地感应位置恢复到该点（系统鼠标仍按游戏模式回中），保留回中冷却；捕获失败或桌面模式不写入相对位置。拖拽仅取消悬停与推压计时，同时继续跟踪位置。原生 hover 回调拒绝冷却期或当前真实鼠标已经离开按钮交互区的陈旧事件，避免动画/回中前排队的事件再次释放输入。

验证：27 项几何、137 项运行检查通过。新增 20 轮完整循环，执行生产展开、收起、事件分支和位置恢复方法；模拟系统捕获回中，每轮仅在边缘附近移动 30pt 即重新展开。恢复旧的 recapture 清零方式，同一回放失败。捕获失败和延迟 hover 也被覆盖；六项相关输入回归通过，Release 构建和严格签名验证通过。日志增加 `Edge sensor resumed` 返回位置。运行回放仍不等同于用户实机验收。
