# 串流边缘控制栏：重复触发后失效

## 现场证据

用户报告两次可见触发后失效。pid 44496 的日志实际记录了五次内部 summon，说明“检测器触发”不能作为“控制栏可用”的验收。

17:44:34.884 和 17:44:39.683 收起并恢复捕获时，当前位置分别为 (1857.2,586.7)、(1854.8,591.4)。二者仍在右侧按钮交互区内。相关证据保存于 `build-input-review/edge-state-incident.log`。

## 本轮修改

- 临时释放后的移动和点击都读取当前系统指针，不再使用可能仍指向捕获中心的旧事件位置。
- 原生 enter/exit 回调重新计算实际悬停状态；自动收起计时器到期也重新计算，不信任缓存的 `edgeMenuPointerInside`。计时器注册到 common modes。
- 展开、收起直接应用最终面板位置，移除能在新状态之后写回旧 frame 的动画完成回调。
- 控制栏、菜单或拖动占用鼠标时，直接捕获和延迟重新捕获统一拒绝执行，覆盖游戏与桌面模式。
- 在按钮上主动关闭后，需要先离开感应区再进入，避免重新捕获后立即自发打开；新会话、正常捕获、尺寸及释放边界仍按既有逻辑清理。
- 保留 C 键确认逻辑、24pt/150ms 悬停和 2pt/30pt 推压，保留从控制栏返回时的感应坐标。

窗口和底层输入使用替身；没有向用户桌面发布合成鼠标事件。这些测试不能替代 WindowServer、真实远端光标和实际串流的验收。特别是游戏模式的本地相对累计位置并非主机光标的权威坐标。

## 定位结果与位置同步修复

PID 48095 的真实复现显示所有入口条件均正常（enabled/captured/visible 为 1，buttons/temp/menu/cooldown 均为 0），但用户在边缘操作时，本地相对累计坐标长期停在 x=1200–1500，视图右边界则为 1920；系统位置始终锁在 (960,540)。根因是将相对游戏鼠标原始量当成了可见光标的位置。相对输入协议没有主机光标反馈，无法保证跟随主机加速、起点与程序重定位。加大增益或放宽阈值不能提供可靠修复。

用户明确选择当前 Desktop 使用位置同步。只修改该主机（86D1F81F-4D3D-E306-D694-EFDFE6BCD6CE）配置 mouseMode: 0→1、freeMouseMotionMode: 0→1，分别表示 remote 和 Desktop Sync；未改变全局配置及其他字段。修改前配置保存在 build-input-review/edge-coordinates-host-profile-before.plist。设置 UI 的辅助功能读取工具在打开偏好设置时崩溃，因此在无串流 UDP 连接时停止应用，通过 defaults 只更新两个已授权字段，再读回并比较全部其他字段。

代码修改：
- 桌面感应统一读取当前系统指针在串流视图内的位置，不使用队列里旧事件或主机虚拟指针。
- 面板绘制与命中检测统一以视图 bounds 为基准；屏幕锚点通过 view→window→screen 转换，取消全屏时改用窗口外框的特例。
- 感应区排除视图以外/非有限坐标，避免副屏位置误触发。保持 24pt 逻辑点阈值，不乘 Retina 比例或远端分辨率。
- 小视图自适应缩小停靠内边距；两处游戏模式中心 warp 使用主屏全局坐标基准，修复副屏高度误用。
- 悬停 timer 加入 common modes，避免 AppKit tracking loop 暂停倒计时。
- 设置说明明确桌面精确位置与游戏模式估算的差异，保留已有游戏相对输入行为及 C 键保护。
