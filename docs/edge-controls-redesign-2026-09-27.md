# 串流边缘控制栏：全面审查与重设计

本轮范围是控制栏的感应、呈现、指针所有权、菜单嵌套循环、拖动、窗口/Space 生命周期和相关 UI。保留已验收的 C 来源过滤、按键配对和配置快捷键。未把完整审查等同于所有实机组合均已验证。

## 发现与处理

| 级别 | 原问题 | 新实现 |
|---|---|---|
| P1 | 24pt 感应覆盖整条边缘，展开按钮的 104pt 深交互区又被并入激活区域 | 独立的 4pt × 56pt 本地激活区域，停留 250ms；展开后的操作区不参与唤出 |
| P1 | 原生 hover 和自由鼠标向外移动各有一条直接展开路径，绕过阈值与开关 | 唤出仅走统一感应器；原生 hover 只维护已展开控件，普通越界只交接鼠标 |
| P1 | 展开、菜单、拖动由独立布尔值控制，可出现互相矛盾的组合 | 独占 Hidden/Collapsed/Expanded/Menu/Dragging 状态，集中清理定时器与面板命中状态 |
| P1 | 菜单嵌套循环中关闭窗口、切换应用或停止串流后，旧完成路径能继续操作 | 生命周期 token 与当前上下文复查；隐藏会取消菜单 tracking；旧完成回调不能重开控制栏 |
| P1 | 锁定游戏鼠标以原始 delta 猜测主机光标，长期漂移 | 删除相对积分及推压预算。锁定时用已配置释放/控制中心快捷键；释放后用真实本地坐标 |
| P1 | 展开控件未必带有临时释放标志，后台重捕获可能抢走指针 | 展开、菜单、拖动均拥有本地指针；恢复意图单独记录，主动释放 latch 保留 |
| P1 | 移动事件立即收起与 0.82s 定时器同时存在；移动还反复重置 deadline | 统一 450ms 离开宽限，返回区域取消；移动不重置期限，点击画面仍可明确恢复 |
| P1 | 自动收起时即使指针在另一块屏幕也会捕获并 warp | 只在串流视图内、无按钮按住且满足捕获条件时恢复 |
| P1 | 快捷键提前释放后，菜单不知道进入前是否捕获，无法正确归还 | 菜单事务统一获取与保存捕获前状态；收起后按该状态恢复 |
| P2 | 普通边缘释放取消悬停 timer，指针停住后没有新移动，入口失效 | 交接后若本地指针仍在激活目标，重新计时；截止时重新验证上下文 |
| P2 | 折叠的透明面板仍可吞点击，收起后还使用展开命中区阻止恢复 | 折叠面板穿透输入；仅展开时使用操作命中区 |
| P2 | 旧 tracking area 从未赋值，nil 比较分支可能误吃正常回调 | 删除控制器的旧 tracking area；把手只保留自身实际 tracking owner |
| P2 | 拖动取消/失败、晚到 mouse-up、小窗口停靠位置缺少一致处理 | 独占拖动阶段；取消与失败收敛；隐藏清理 press；共享自适应内边距 |
| P2 | mouseMoved 反复写相同外观、重复 setFrame，保留完全透明的装饰图层 | 属性/位置未变则跳过；删去无视觉贡献的曲线和渐变层 |

## 行为约定

- 四边均用串流 view 的逻辑点；不按远端像素、Retina 倍率或分辨率放大。
- 折叠把手为细标记，展开尺寸 56×56pt。只有对应一段边缘触发。
- 无按钮按下、本窗口可交互时才启动悬停；跨显示器、非有限位置和尺寸变化均重新验证。
- 主动释放不会被自动收起、焦点恢复或悬停取消。点击串流画面才恢复。
- 右键仍是远端鼠标输入；不会重新引入“释放后每次右键弹本地菜单”。
- 游戏锁定模式没有远端光标反馈。用户尚未回复锁定模式偏好问题，本轮采用已告知的安全默认：不猜位置，按现有快捷键进入本地控制。后续若需要推压，应设计为独立、有明确反馈的手势，不能宣称与主机光标位置一致。
