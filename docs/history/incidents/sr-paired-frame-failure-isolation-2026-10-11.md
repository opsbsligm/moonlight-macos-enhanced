# 原始帧与插帧的超分失败隔离

原始帧和生成中间帧共享源序号，但不是同一张图像。旧 SR 去重只保存一个失败源序号：中间帧超时后，同源原始帧也被拒绝超分；反向也成立。

现在分别记录原始帧和中间帧的失败序号，配置退休时同时清零。单张失败帧不会重复排队；两张均超时也各自保留记录，不因另一张失败覆盖记录再重试。全局单 flight、共享排队/计算期限、硬失败立即熔断与连续过载熔断均保持不变。

原生门禁抽取生产 renderer 方法，使用真实 CV buffer 和 dispatch、确定性后端 double。两种超分引擎、两个失败方向及另一张成功/超时共八种场景；拒绝恢复按源序号共用标记及错误保存帧类型两个可编译负变异。

证据边界：这些测试验证调度与生命周期，不证明真实 VT 图像质量或串流到屏流畅。构建、综合回归、冷分析及 CI 按各自最终日志记录。可单独 revert 本轮提交，但会恢复失败相互污染。

## 原生替身的运行时隔离

SR/FI 替身现在分别注册为 `MLTestSR...` / `MLTestFI...`，不与系统 VideoToolbox 的 Objective-C 类重名。宏仅作用于原生测试翻译单元，抽取的生产方法原文、真实 VT 路径均未改名。

每种替身均通过 `NSStringFromClass` 验证实际运行时身份；门禁拒绝 stderr 的重复类注册警告。将处理器映射为另一个合法、唯一类名的负变异必须编译成功但因身份不符失败，不能让运行时偶然选到系统类后仍算通过。
