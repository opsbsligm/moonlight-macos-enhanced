# 连击发送 C：现场回归与修正

> 后续实机反馈：用户在 C guard 版本安装后确认“可以了”；之后反馈的是串流边缘控制栏缺失，已作为独立问题处理。


用户反馈：左键恢复，但连续点击仍发送 C；拔掉鼠标接收器后，MacBook 触控板也会出现。此前按 AJAZZ 来源过滤的修复不足，不能视作问题已经解决。

## 本次确证

- 已安装版本进程 `35318` 的串流日志记录了 **20 次 C keyDown，0 次 C keyUp**，20 次均由约 120 ms 后的键态补偿释放。C 已经先发往宿主，补发 UP 不能撤销它。
- 这些事件已经到达 `StreamViewController keyDown:`，通过了 NSEvent 类型检查；不能再将它们解释为“读取鼠标 event.keyCode”的同一个问题。
- 同次日志明确记录 Input Monitoring 未授权，因此依赖 IOHID 的设备来源过滤器未启动。原默认设置又未开启通用键态暂缓，不完整 C 就会直接通过。
- 生产方法回放在修改前稳定失败：默认设置、没有监听器、没有物理按住证据、仅 C DOWN，仍产生 `8043D 8043U`。修正后同一序列不产生包。

## 实际修改

`HIDSupport.m` 对无设备来源监听路径的 C 默认启用现有确认机制：物理 C 已按住时立即发送；未按住时暂缓，60 ms 内的真实 UP 确认快速点按并发出完整 DOWN/UP；后续物理按住证据也可确认；一直没有证据则本地丢弃。其它键维持原策略，不把 C 转成点击，不消耗原本的鼠标点击。已启用的设备来源过滤保留原仲裁策略。

在 AppKit 的 C 入口增加事件时间、底层 CGEvent 类型、来源 PID、HID/会话键态日志。只为 C 增加来源字段，不记录其它键的字符内容。移除代码注释中“永久关闭所有漏洞”等没有证据支持的表述。

`scripts/probes/c-input-source.m` 是有时限的只读取证工具，只观察左键和 C，拒绝未授权运行，不主动请求权限。可用 macOS SDK 编译，并传入观察秒数（最多 300 秒）。

## 验证与剩余不确定性

- 45 条专项回归命令通过；键盘回放新增默认配置下的 20 次不完整 C、真实快速点按、物理长按、丢弃后继续正常输入；撤销默认 C 防护的负向变体必须失败。
- Release 构建、第一方源码告警检查及严格签名校验通过。对应日志为 `build-input-review/c-guard-*`。
- `c-reproduction-existing.log` 保留已有串流中相关键鼠证据；`c-source-probe.log` 保存本次有时限来源观察。观察期间只录到 AJAZZ 普通点击和 HS USB Dongle 的一组真实 C 按下/抬起，没有录到用户所述“接收器拔掉后的触控板连击异常”。**异常 C 的原始来源仍未查实。**
- 防护依赖事件配对和物理键态；如果异常事件也能提供真实按住状态或完整键对，它不应被宣称已被本修复覆盖。特殊软件注入的不配对 C 也可能被拒绝；来源诊断用于进一步区分，不用设备型号推断用户行为。
- 这次结果证明已知发送路径的回放通过，不等于触控板/接收器两种实际场景已验收。
