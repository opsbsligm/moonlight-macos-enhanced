# USB 数值确认的精确性（2026-10-11）

## 本阶段改动

生产策略能力读取与会话确认读取，均仅接受数值精确为 1 的 NSNumber；不再先转换整数。旧读法会把 1.01、1.9 截断为 1，错误放行。

使用 `compare:[NSDecimalNumber one]`，保留布尔 YES、整数 1、浮点 1.0、十进制 1。不能改为 `isEqualToNumber:@1` 或 `compare:@1`：本机 Foundation 对十进制 `1.00000000000000000000001` 与普通 @1 比较会舍入，而与十进制 one 比较能保留差异。字符串协议及槽位整数检验未变。

## 可执行验证

- 策略原生测试拒绝 1.01、1.9、0.99、-1、NaN、正负无穷及高精度微小小数；接受三种真正数值 1。
- 会话原生测试以独立预期驱动以上 11 个答案，分别覆盖能力、绑定、设备确认，共 33 个状态场景。
- 两套门禁均加入可编译负变异：恢复整数截断、退回普通 NSNumber 等值比较。负变异必须失败，不能仅靠静态匹配宣称行为正确。
- Debug 构建成功；冷启动分析实际覆盖 94 个文件，38 个既有已说明 finding，0 analyzer audit failures。

## 验收边界与回滚

原生状态机及参考主机环回不等于真实 USB 直通。DriverKit 签名、公证和真实主机通道仍未满足，不因此启用连接。

本轮 Cua 运行时重置后重新绑定 QA 应用仍报告 native pipe closed，真实 GUI 不记通过。综合回归和 CI 以实际日志终态为准，不以启动命令代替结果。

可单独 revert 本阶段提交；回滚会重新引入上述截断误判，不建议作为常规降级。
