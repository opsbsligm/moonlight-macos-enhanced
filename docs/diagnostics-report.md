# 诊断报告：内容、采集前提与脱敏规则

> 读者：准备反馈问题的使用者（想知道报告里到底有什么、会不会泄露隐私），以及需要读报告的支持者。
> 入口与提问清单见 [`../README.md`](../README.md)「如何反馈」。本页内容自 `README.md` 搬移而来（2026-09-24 文档信息架构重构）。本页已对照代码复核（2026-09-24），并补进搬移之后才出现的 `devices` 段。

## 报告入口

`设置 → 应用 → 调试日志 → 拷贝诊断报告…` 会把一份可直接粘贴的报告放进剪贴板；配对失败的弹窗里也有同一个按钮。

## 一份报告包含哪些内容

App 版本与构建号、macOS 版本号、机型、是否被 Gatekeeper 以只读转译目录（App Translocation）方式运行、
输入监控 / 辅助功能 / 屏幕录制当前的授权状态、Info.plist 声明的 Bonjour 服务（其中是否包含
`_nvstream._tcp`——“别的客户端能发现主机而这里不能”这类问题最先要看的就是这一条）、
一个 `input` 段（当前生效的鼠标策略与其存储值、CoreHID 是否被允许 / 是否尝试启动 / 是否真的送出过移动 / 失败原因，
以及最后一次真正把移动交给主机的发送者是谁、发生在多久之前），
已配对主机及其配对与在线状态，以及 App 自身日志的末尾若干行。

`devices` 段放的是设备页那条审计行的**原文**（当前包的签名形态、规则条数、读不懂的记录条数、
放行的接口类别数、本地输入设备开关，以及四个前置条件里第一个还没满足的是哪一个）——复用同一行
而不是换个说法重述，是为了让两边没有各自漂移的空间。它另外带两行边界声明：报告不会去问主机
（所以没问过就写 `host-not-asked`），也不会去扫 USB 总线（所以没扫就写 `not-scanned`）。这两行是
刻意印进报告的：一个读起来像「没插设备」的设备段，会让人去拔已经拔过的那根线；而一个从没人
联系过的主机若被写成「拒绝」，会把人支去翻那台根本没作答复的机器的设置。逐台设备的明细**不在**
报告里：报告不扫总线，也不输出任何设备标识。

## 输入诊断开关是采集前提

**如果问题是鼠标不动，请先打开 `设置 → 应用 → 调试日志 → 输入诊断（Input Diagnostics）` 再复现一次，然后拷贝报告。**
`input` 段里的逐发送者计数只有在开关打开时才采集；报告不会在没采集的时候打印一堆 0——那些 0 看起来会像“鼠标从未移动”，
而事实是“没人计数”。

## 脱敏规则

报告在离开本机前会被脱敏：PIN、口令 / passphrase / secret / token、客户端与服务端证书字段、
`unique id` 与 `client id`、形似 base64 的长串、MAC 地址、UUID（保留前 8 位，便于把同一台设备的
两份报告对上）以及用户主目录路径，都会被替换成 `[redacted-pin]`、`[redacted-uuid]` 这样的标记。
主目录不只按 `/Users/...` 前缀匹配——还会拿**本次运行实际解析出的那个主目录**做精确替换，所以不
在 `/Users` 下的家目录（开发机与 CI runner 就是这种）同样被抓；`/private/var/folders/...` 也会被
换成 `[redacted-path]`，那正是 Gatekeeper 用 App Translocation 运行时的路径形状。主机 MAC 地址、
证书与客户端标识三个字段则根本不会被读取。主机名与地址会保留——去掉它们的连接报告无法定位问题。

还有一条值得写下来：某条脱敏正则如果构造失败，报告**不会**假装干净，而是在末尾追加
`[redaction rule unavailable]`。「扫不动」永远不被读成「没东西可扫」，这条原则在本仓库到处都在用。
